# EquipmentCounter — описание PDF-пайплайна

## 1. Что за продукт

**EquipmentCounter** — система автоматического составления **ВОР (Ведомость объёмов работ)** по электротехнической части (ЭО, ЭМ, ГПК) на основе CAD-чертежей в PDF/DXF.

Входы:
- PDF и DXF файлы инженерного проекта (планы освещения, привязки, лотков, схемы, ГПК).
- Папки вида `Data/<раздел>/<захватка>/02_PDF/*.pdf`.

Выходы:
- DOCX и XLSX по «эталону» проектировщика (альбомная А4, 7 колонок, разбивка по разделам).
- Веб-интерфейс на FastAPI с просмотром PDF, разбором легенды, агрегацией ВОР и кнопками экспорта.

## 2. Веб-приложение (точки входа)

| Файл | Роль |
|---|---|
| `web_app.py` | Базовое FastAPI-приложение: реестр PDF, рендер страниц через PyMuPDF, парсинг легенды, SSE-обработка папки. Слушает `:8050`. |
| `run_web.py` | Расширение №1: подменяет рендер DOCX на эталонный (`vor_docx_renderer`), пере-агрегирует формулу ВОР по строительным отметкам (`vor_elevation_grouper`), подключает middleware и эндпоинты экспорта. |
| `run_web_v2.py` | Расширение №2: поверх `run_web.py` добавляет инжекцию строк «Кабель по вертикали (стояки)» (`vor_height_injector`). **Текущий рекомендуемый launcher.** |
| `run_web_with_height.py` | Альтернативный экспериментальный launcher с тем же назначением. |
| `web_app.bat`, `web_app_v2.bat`, `web_app_v3.bat` | Batch-launcher'ы: убивают занятые порты и стартуют соответствующий entry-point. |
| `vor_export_patch.py` | Регистрирует `/api/folder/{id}/export_xlsx_v2`, `/export_docx`, `/cache_vor`. Кэш агрегата по folder_id (TTL 30 мин). |
| `vor_inject_middleware.py` | Starlette-middleware, инжектит `<script src="/static/vor_patch.js">` в HTML-ответы `/`, не правя `index.html`. |
| `web/static/vor_patch.js` | Клиентский патч: переопределяет `startVor`, добавляет кнопку DOCX, по событию `done` дёргает `/cache_vor`. |
| `web/templates/`, `web/static/` | HTML/CSS/JS интерфейса. |

**Цепочка патчей `get_cached_vor`:**
```
оригинал (vor_export_patch)
  → run_web._get_cached_with_elevation       # формула по отметкам
    → run_web_v2._get_cached_with_heights    # + строки вертикальных стояков
```

## 3. PDF-движок: разбор чертежа

### 3.1. Извлечение легенды («Условные обозначения»)
| Файл | Что делает | Алгоритм |
|---|---|---|
| `pdf_legend_parser.py` | Ядро: находит таблицу легенды, парсит строки «Обозначение / Наименование». | `pdfplumber` — поиск прямоугольников/линий PDF (rects/lines), кластеризация в строки. Поддержка многострочных описаний. |
| `legend_validator.py` | Проверяет, что каждая строка легенды уникально идентифицируема: либо текстовый маркер, либо визуальный шаблон, либо цвет. | Парные сравнения. |
| `template_library.py` | Строит и кеширует bitmap-шаблоны иконок прямо из легенды каждого PDF (для последующего поиска). | Отрисовка крепа из легенды через PyMuPDF. |
| `diagnose_legend.py` | Диагностика — рисует найденные bbox'ы строк легенды поверх PDF. | — |

### 3.2. Подсчёт оборудования
| Файл | Что делает | Алгоритм |
|---|---|---|
| `pdf_count_text.py` | Считает тексто-меченые символы (`5А`, `3`, `1А`...) в зоне чертежа, исключая легенду и угловой штамп. | Поиск регексов по словам PDF, фильтрация по координатам. |
| `pdf_count_visual.py` | Считает графические символы (для ЭМ-чертежей без текстовых меток). | Шаблонный matching: вырезает иконку из легенды, рендерит страницу в PNG, ищет через OpenCV `matchTemplate` (NCC). |
| `pdf_count_geometry.py` | Считает оборудование по геометрическим признакам (квадраты, треугольники). | Анализ rects/lines из PDF. |
| `pdf_color_layers.py` | Разделяет PDF на цветовые слои (red / blue / black / grey) для целевого поиска по слою. | HSV-сегментация после рендера в PNG. |
| `equipment_counter.py` | Главный CLI-фасад: парсит легенду и диспатчит подсчёт по подходящему методу. | Объединяет всё вышеперечисленное. |

### 3.3. Кабельные трассы
| Файл | Что делает | Алгоритм |
|---|---|---|
| `pdf_count_cables.py` | Извлекает аннотации кабелей (сечение, марка, группа). | Регекс по словам PDF возле трасс. |
| `pdf_cables_by_method.py` | Главный модуль: измеряет длины красных/синих трасс с разбивкой по способу прокладки и сечению. | Извлечение полилиний из PDF (PyMuPDF), фильтр по цвету (RGB), масштаб из текста размеров (`6000` мм между осями), дедуп параллельных линий и точных дублей, T-tick маркеры. |
| `pdf_cable_annotations.py` / `_v2.py` | Извлекает аннотации «Гр.X-Гр.Y на отм. 0.000, +9.000, ...». Первая версия (pdfplumber) не работала на CAD-PDF; v2 — улучшения. | — |
| `pdf_cable_height.py` | **Текущий рабочий извлекатель**: достаёт аннотации через `fitz.get_text("dict")`, мерджит 2-строчные блоки, фильтрует тексты картуша, считает высоту стояков. | `riser = max(elev) − min(elev)`, `total = riser × n_groups`. Цвет — по доминирующему RGB span. Глобальная дедупликация по `(groups, elevations, color)` чтобы не считать стояк 7 раз с 7 этажных листов. |
| `vor_cable_corrections.py` | Page-level коррекция длин из `measure_cables` по аннотациям (мультипликатор × N этажей). | — |
| `vor_measure_wrapper.py` | Обёртка над `pdf_count_geometry.measure_cables` с применением коррекций. | — |
| `compare_cables_vor.py` | Сверка PDF-длин с эталонной .xlsx-ВОР построчно. | — |

## 4. Сборка ВОР (после извлечения)

| Файл | Что делает |
|---|---|
| `vor_generator.py` | Главный генератор: собирает оборудование из всех файлов проекта, группирует по типу + монтажной высоте, формирует DOCX. |
| `vor_work_mapping.py` | Словарь сопоставлений: `имя из легенды` → `работа из ВОР` (двухуровневая структура работа/материал). |

| `vor_docx_renderer.py` | Рендер «по эталону»: альбомная А4, поля 2/2/0.8/0.3, Times 12pt, 7 колонок, разделы (Щитовое / Светотехническое / Установочные / Кабельная продукция / Лотки / ПВХ / Пусконаладка), подписи. |

| `vor_height_fix.py` | Старая версия пере-распределения светильников/кабелей по категориям высоты. |
| `vor_compare_excel.py` | Сравнение эталонной vs сгенерированной ВОР с подсветкой расхождений в Excel. |
| `analyze_vor_details.py`, `analyze_vor_patterns.py`, `parse_vor_improved.py` | Анализ структуры эталонных ВОР для извлечения паттернов. |

## 6. Ключевые алгоритмы (резюме)

1. **Парсинг легенды** — pdfplumber rects/lines → строки таблицы → текст в колонке наименований.
2. **Подсчёт оборудования** — три стратегии: текстовые маркеры (regex), визуальный matchTemplate (NCC), геометрия (счёт rects).
3. **Цветовые слои** — HSV-сегментация рендера PDF; красный = аварийное, синий = рабочее.
4. **Длины трасс** — извлечение полилиний PyMuPDF, фильтр по цвету RGB, масштаб из текста размеров, дедуп параллельных и дубликатов.
5. **Высота стояков** — `fitz.get_text("dict")` → мердж 2-строчных аннотаций → парсинг `Гр.X-Y на отм. ...` → `(max−min) × n_groups`. Глобальная дедупликация по `(groups, elevations, color)`.
6. **Группировка ВОР** — по строительным отметкам, вытащенным из имён файлов регексом.
7. **Эталонный DOCX** — таблица 7 колонок с разделами по правилам regex-маршрутизации (Щитовое / Светотехническое / Кабельная продукция / Лотки / ПВХ / Пусконаладка).

## 7. Куда развивать дальше

### Срочное (нерешённые баги)
1. **Слишком агрессивный merge_multiline_blocks в `pdf_cable_height.py`** — на лст 006 ГПК даёт 65 групп вместо ожидаемых 27, метраж завышен ×2.4. Нужно сужать `max_dy/max_dx` или анализировать межстрочные интервалы.
2. **Аннотации не привязаны к конкретным полилиниям** — сейчас высота умножается на `n_groups` из текста, но не сопоставлена с реальными трассами на чертеже. Нужен матчинг «аннотация → ближайшая полилиния её цвета», тогда множители применятся корректно к каждой трассе отдельно.
3. **Параллелизация SSE-обработки папки** в `web_app.api_folder_process` — сейчас sequential, нужен `ProcessPoolExecutor`.
4. **GPK3 «Лотки» — overcount** при подсчёте лотков (старая запись в `known_bugs.md`).
5. **Hygiene-audit** — в репозитории много `_test_*.py`, `_diag_*.py`, `_probe_*.py`, `temp_*.py` (≈100 файлов scratch). Нужно вынести в `experiments/` или удалить.

### Среднесрочное
6. **Унификация cable detector** — три модуля (`pdf_count_cables`, `pdf_count_geometry`, `pdf_cables_by_method`) делают пересекающиеся вещи. Слить в один движок с явным API.
7. **Per-PDF template library** (`template_library.py`) пока опционален — включить по умолчанию для ЭМ-чертежей.
8. **Унификация `run_web*.py`** — три launcher'а (`run_web`, `run_web_v2`, `run_web_with_height`) с пересекающимися патчами. Свести в один с флагами/конфигом.
9. **Покрытие тестами** — много ad-hoc `test_*.py`, нет CI. Перейти на pytest + GitHub Actions.
10. **Конфиг словарей** (`vor_work_mapping.py`) сейчас захардкожен — вынести в YAML/JSON, чтобы инженеры могли править без правки кода.

### Долгосрочное
11. **DXF-ветка как ground truth** уже есть (`dxf_ground_truth.py`) — расширить покрытие, регулярно прогонять PDF accuracy benchmark.
12. **Многоэтажные проекты** — сейчас захватки и этажи определяются эвристикой по имени файла. Нужна явная структура проекта (manifest.yaml в корне папки захватки).
13. **Схемы (однолинейные)** — пока не парсятся; добавить распознавание «щит → отходящие линии → кабели».
14. **Обнаружение масштаба** — сейчас один масштаб на лист из текста размеров. Поддержать несколько фрагментов разного масштаба на одном листе.
15. **Веб-UI** — добавить редактирование агрегата ВОР перед экспортом (drag-drop разделов, ручная корректировка формул).

## 8. Зависимости

- **PyMuPDF (fitz)** — рендер, текст с координатами и цветом, полилинии, экспорт в PNG.
- **pdfplumber** — извлечение rects/lines/words для легенды.
- **ezdxf** — DXF-парсер.
- **OpenCV / numpy** — visual matching, цветовая сегментация.
- **python-docx**, **openpyxl** — генерация DOCX/XLSX.
- **FastAPI / Starlette / uvicorn** — веб-приложение.
- **ODA File Converter** (внешний) — DWG → DXF в `batch_processor`.
